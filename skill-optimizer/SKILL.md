# skill优化器（Skill Optimizer）

## 核心思路

看到重复工作，第一自问：**是否可以标准化封装为可复用 skill / 脚本 / 规则？**
本 skill 目标：消除人肉重复劳动，产出可复用资产，**禁止无授权静默修改本地文件**。

## Step 1：扫描重复（带量化判定）

扫描对象：当前对话上下文、任务复盘、历史任务片段。

**量化阈值：仅当同一类行为出现 ≥2 次才判定为重复；出现 1 次或一次性任务直接终止本 skill，不继续后续步骤。**

两类目标：

1. **重复工作（适合脚本化）**
   - 特征：确定输入 → 确定输出；可参数化；结果可验证；人工反复执行同类操作。
   - 例子：批量格式化、模板代码反复抄写、重复编译校验、固定流程数据处理。

2. **重复问题（适合提炼终止条件规则）**
   - 特征：同类错误/同类拉扯反复发生；缺少明确停止/询问边界；不是任务本身固有的复杂度。
   - 例子：同一工具报错反复重试；清单与实际文件不一致强行补全；同一结论循环反复辩论。

**必须产出扫描记录表**，每项含：

| 字段 | 内容 |
|---|---|
| 重复项描述 | 什么操作/问题 |
| 重复次数 | 实际计数 |
| 根因 | 为什么会反复发生 |
| 分类标记 | `work(脚本化)` / `problem(规则化)` |

## Step 2：分类处置

### 2a 重复工作 → 脚本化判定

满足**全部三条**才适合写脚本：

1. **确定性**：相同输入得到可复现输出；
2. **参数化**：对外暴露参数，禁止硬编码路径、文件名；
3. **可验证**：存在明确成功判定标准（diff 校验、编译通过、断言校验等）。

> 不满足任意一条：放弃脚本化，改为输出**人工操作清单**，不生成代码。

脚本约束：

- 存放位置：目标 skill 目录下 `scripts/`；
- 必须支持**预览模式（dry-run）**，默认不直接修改真实文件；
- 修改文件前必须**内置备份逻辑**（复制带时间戳的副本）。

### 2b 重复问题 → 终止条件规则（固定格式）

每条规则强制**二元结构**，一句话完成，拒绝长篇大论：

> 【触发条件】：xxx 场景发生时
> 【动作】：直接停止 / 向用户确认 / 抛出告警，禁止继续原有流程

禁止写成模糊建议，必须明确「停 / 问 / 告警」。

### 2c 落点判定（优先复用已有，禁止盲目新建）

> 新建 skill 前必须执行检索，禁止直接新建。

1. 检索两处位置：
   - 全局复用：`~/.dsh/skills/`
   - 项目局部复用：`.agents/skills/`
2. 命中已有相似 skill：**迭代更新已有 skill**，脚本/规则并入，更新 SKILL.md，不新建；
3. 无匹配 skill：调用 skill-creator 的 `init_skill.py` 初始化新 skill，严格遵守 frontmatter 只保留 `name`、`description`；
4. 选址：跨项目长期复用放全局目录；仅本项目内使用放项目本地目录。

> 多步骤复杂流程：引用 skill-creator 的 `references/workflows.md` 设计。

## Step 3：验证与落地（权限约束）

> ⚠️ **没有用户明确许可，只输出方案文本，不执行写文件、生成脚本、打包、修改磁盘的任何操作。**

### 用户授权后才执行真实落地

1. 脚本：使用代表性样本做运行测试；测试中间文件隔离（放工作目录），不污染 skill 源码目录；提供 dry-run 预览输出。
2. 更新 SKILL.md：新增小节描述新增能力、写明触发场景，同步更新 description 补充触发关键词。
3. 可选：用 skill-creator 的 `package_skill.py` 打包分发；用 `quick_validate.py` 校验 skill 结构与 frontmatter 合法性。

### 未授权场景（默认状态）

只输出：扫描记录表 + 脚本伪代码/规则文本 + 建议存放位置。**仅方案输出，不触碰磁盘。**

## Step 4：输出契约（强制输出结构）

调用本 skill 后，输出必须包含 4 块：

1. **重复扫描结果表**（Step 1 的记录表）；
2. **分类处置方案**：哪些脚本化、哪些转为终止规则；
3. **落点规划**：复用哪个已有 skill / 需要新建 skill，存放路径；
4. **落地状态**：【仅方案展示，待用户确认执行】 / 【已获得授权，完成落地】。

> 弹性：简单场景（仅 1 个重复项）可精简第 1–3 块为一段话，但**第 4 块「落地状态」必须保留**。

## 案例

### 案例 1｜重复工作 → 脚本，更新已有 skill
- 现象：LaTeX 参考文献手工格式化，37 条逐条处理，重复操作多次。
- 扫描记录：重复次数 ≥2；根因：手工解析 bib 条目、核对 DOI 信息机械重复。
- 处置：开发 `ref_format.py`，支持 dry-run 预览、自动备份，调用 Crossref 批量补信息。
- 落点：已有 `academic-paper-completion` skill，脚本放入其 scripts 目录，更新 SKILL.md。

### 案例 2｜重复问题 → 终止条件规则
- 现象：工具返回同一个报错仍反复重试；清单条目与实际文件数量不一致强行补内容；同一结论无限拉扯。
- 输出规则示例：
> 【触发条件】同一工具报错连续出现 2 次
> 【动作】停止重试，向用户报告错误，不再继续调用该工具

> 【触发条件】清单条目数量与真实文件条目数量不一致
> 【动作】停止自动补全，先向用户核对原始清单

> 【触发条件】同一逻辑结论已经来回讨论两轮以上
> 【动作】停止循环推演，直接输出当前结论，询问用户是否接受

- 落点：通用行为约束 → 项目规范「通用总则」。

## 边界约束

1. 只出现 1 次的任务、一次性任务直接跳过，不做自动化；
2. 用户没有明确要求自动化，**绝不自动落地脚本、修改磁盘文件**；
3. 本 skill 是流程编排 skill，本身不内置业务脚本，脚本是产出物；
4. 严格遵守优先更新已有 skill，新建 skill 必须先检索确认无同类能力；
5. 脚本化判定不通过，禁止强行写脚本，降级为人工操作清单；
6. 不处理高度主观、无确定输出的任务，这类不适合脚本化。
